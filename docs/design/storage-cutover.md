# 存储切换与回退

存储变更有两个操作。改变默认写入位置，让新资产去新位置，旧资产继续按各自位置访问。迁走旧数据，则须先复制并验证，再把已有记录改指向目标位置。两种操作都保留 `fileId`、对象 key 和业务关联。

## 先切换写入位置

1. 以不同位置 ID 注册源和目标，确认目标的目录、桶、权限和可用空间。保持原默认位置启动一次，让新位置与实际存储的绑定写入 SQLite。配置见 [文件存储平台设计](storage-platform.md)。
2. FileServer 对同一 SQLite 数据库按单实例运行。暂停业务侧提交和外部录制直传，等待或安全停止 Worker，保留它的持久数据目录。核对未完成的分段上传和确认任务，处理完在途写入再停 FileServer。停止文件服务也会停止它的清理任务。切换及回退期间避免旧、新两个进程同时写同一个数据库。
3. 修改 `mfs.storage.default-location`，有录制时协调 `mfs.reception.location` 和业务系统配置的 S3 直传地址、桶及录制身份。重启验证旧 `fileId`、预览和接收任务，再恢复流量。恢复旧默认值也用同样的停写流程，切换期间新建的资产保留自己的位置，原、新位置都继续配置。

使用现有 v1 直传协议时，仍需要旧路由续传的录制任务须先完成或取消。如果旧任务已经收齐原始对象，只等待确认，FileServer 按任务记录继续从原接收位置读取。需要把任务和原始对象一并迁移时，走下面的流程。

## 再迁移已有数据

1. 按上面的停写步骤停掉参与方。生成一致的 SQLite 备份，并保存当时的 FileServer、Worker 和存储配置。对存储做快照或保留源数据。未完成的 S3 multipart 上传不在普通对象列表内，须在此之前完成或确认废弃。核实两位置是否指向不同的实际数据集。不同 URL 或网关可能连接同一个桶。
2. 复制前对下面的命令加 `--preflight`，核对位置角色及正式对象 key 是否与目标已登记的文件、预览或候选记录冲突。预检只查 SQLite，复制时还须使用禁止覆盖的方式。保留对象 key，复制正式对象、预览、候选副本和受影响接收任务的完整前缀。目标已有同名对象时，核实字节完全一致才可复用，内容不同就停止处理该冲突。两个地址指向同一实际数据集时，可直接核对引用，无需复制。
3. 去掉 `--preflight`，使用发布包内的 `scripts/storage_cutover.py` 验证源和目标。预检和纯本地存储核对使用 Python 3.10+，核对 S3 时还要安装 `boto3`。凭据读取 AWS 配置或运行环境，可用 `--profile 位置=配置名` 为不同后端分别指定。验证身份需要对象读取及接收前缀列举权限。

```sh
python3 scripts/storage_cutover.py /data/muyun-fileserver/var/data/muyun-fileserver.db \
  --move source-files=target-files --move source-receptions=target-receptions \
  --profile source-files=source --profile source-receptions=source \
  --profile target-files=target --profile target-receptions=target
```

4. 对照输出的角色、位置和已核对对象数，在保持停写的情况下给同一命令加 `--apply`。工具再次比对对象大小及 SHA-256，并用一个 SQLite 事务更新所有 `--move` 的位置引用。它会保留原始文件、生成的预览、候选副本、任务 ID、任务状态以及已有媒体资产之间的关联。原生 PDF 的预览引用由主文件验证，切换时清除受影响的缓存引用，下次查看时重建。
5. 按新默认位置和业务直传配置重启。验证历史 `fileId`、预览、在途任务确认和新文件，复核 Worker 已登记的结果可以下载，之后恢复录制和清理。数据库仍有引用的位置必须保留配置。

## 回退与数据保护

- **只改过默认位置。** 停写后切回原默认值和原直传配置，同时保留两个位置。已写到新位置的文件仍能访问。
- **已迁移位置引用。** 可以先切回默认写入位置并保留两边。需要把历史引用也迁回时，再次停写。先对反向 `--move` 运行 `--preflight`，再把目标上的当前数据同步回旧位置，包括切换后新增文件和在途按前缀写入的对象。反向复制也须核对已存在的对象，避免覆盖仍被引用的数据。缺对象、内容不同或任一前缀多出对象，验证会失败。
- **回退存在同名内容差异。** 例如切换后录制端更新了索引，可在原存储服务上注册一个空位置作为回退目的地，同时保留旧副本和当前任务。按同一流程把当前数据迁到此空位置。
- **退役源位置。** 两个实际数据集独立时，在确认源无引用、回退保留期已过且备份可恢复后，再单独安排源数据清理。同一个桶或目录改访问地址时，只退役旧路由或旧凭据，保留仍在使用的数据集。工具只比较配置的地址与对象，无法证明两个地址背后的物理存储独立。
- 对账以当前数据库为准。以旧数据库备份覆盖已恢复写入的现场，会丢失切换后创建的记录。只有在确认尚无新写入，或已保全并能恢复这些写入时，才应用旧快照。

## 隔离演练

2026-11-15 用固定版本的 MinIO 和 SeaweedFS 4.48、独立 FileServer 进程及合成媒体执行 MinIO → SeaweedFS → MinIO。验证历史 ID、生成的 PDF 预览、待确认任务、候选对象和六个 Worker 媒体结果。先切回默认写入位置，确认新旧位置的文件仍可读；反向迁移先因缺少切换后的新对象被拒绝，补齐后完成回退。演练使用隔离数据库和存储，真实站点依上面流程单独核对。
